# 누락 관리형 마켓센싱 조사 운영 원칙

이 문서는 수학적 Q-learning이나 Q값 갱신 알고리즘을 구현하는 명세가 아니다. 제한된
조사비용을 정보가치가 높은 미확인 영역으로 재배분하고, 확인하지 못한 영역을 상태로
남기는 적응 탐색 개념만 차용한 마켓센싱 실행 규칙이다.

## 목적

마켓센싱 조사의 목표는 인터넷 전체를 읽는 것이 아니다. 중요한 외부 변화를 놓칠 수
있는 탐색 공간을 명시하고, 의사결정을 바꿀 가능성이 큰 빈칸에 조사 비용을 집중하며,
확인하지 못한 범위와 중단 이유를 재현 가능하게 남기는 것이다.

사용자가 단순히 `조사해`, `최근 변화 찾아봐`, `자료를 더 쌓아봐`라고 요청해도 이
운영 원칙을 기본 적용한다. 사용자가 조사 채널·기간·출처·비용을 명시적으로 제한하면
그 제한을 우선하되, 제한 때문에 남는 고위험 미확인 범위를 결과에 밝힌다.

완전성은 `인터넷 전체 확인`이라는 주장으로 표현하지 않는다. 다음 세 가지가 확인된
상태를 조사 완전성으로 본다.

1. 중요한 의사결정 영향 경로를 탐색 공간으로 표현했다.
2. 고위험 빈칸을 우선 확인하고 결론을 바꿀 후보를 원문으로 검증했다.
3. 미확인 범위, 접근 실패, 편중, 중단 조건과 다음 재탐색 트리거를 기록했다.

## 항상 적용하는 짧은 원칙

- 발견 전에 `회사 → 사업축·경영 Function → 변화 카테고리 → 지역·시장 → 시간`의
  탐색 지도를 만들고, 결과를 시간순 URL 목록으로 바로 제시하지 않는다.
- 후보마다 사업보고서·IR·공식 포트폴리오 자료로 확인한 회사 노출 근거를 붙이고
  `핵심 관심`, `조건부 관심`, `비대상` 중 하나를 판정한다.
- 회사의 제품·자산·고객·조달·기술·지역·투자계획과 연결되지 않고 바꿀 결정도 없는
  사건은 핵심 Signal·전략 이슈 승격 후보에서 제외한다.
- 인터넷 전체를 확인했다고 주장하지 않는다.
- URL 수보다 의사결정과 전략가정의 커버리지를 우선한다.
- 가능한 조합을 모두 만들지 않고 영향 경로가 성립할 때만 탐색 셀을 생성한다.
- 검색되지 않았음을 사건 부재의 증거로 사용하지 않는다.
- 신규 URL과 신규 정보를 구분하고 같은 사건의 재인용을 성과로 세지 않는다.
- 대상 회사 발표와 외부 시장 Signal을 분리한다.
- 고영향 후보는 원문을 확인하고 최소 한 번 반증 방향으로 탐색한다.
- 발표와 승인·자금·건설·가동·출하·손익 인식을 서로 다른 상태로 본다.
- 중요한 미확인 범위와 오래되어 다시 확인해야 할 상태를 숨기지 않는다.
- 추가 검색의 예상 정보가치가 낮아진 근거와 다음 재탐색 트리거를 남긴다.

## 의사결정에서 탐색 셀까지

조사 순서는 다음 계층을 따른다.

`의사결정 질문 → 핵심 전략가정 → 전제변경 패턴 → 영향 경로 → 동적 coverage cell → 쿼리·출처`

조사를 시작할 때 run에 다음 `decision_context`를 먼저 기록한다. 의사결정이 아직
구체화되지 않았다면 공개정보로 판단 가능한 임시 질문을 세우고 `provisional: true`로
표시한다. 질문을 만들 수 없을 정도로 영향 경로가 약한 주제는 탐색 우선순위를 낮춘다.

```json
{
  "decision_context": {
    "decision_question": "인도 자동차강판 시장 대응 시점을 앞당겨야 하는가?",
    "decision_horizon": "YYYY-MM-DD 또는 분기·연도",
    "business_exposure": ["가격", "물량", "계약"],
    "key_assumptions": ["자동차 생산 증가", "현지 공급 증설 속도"],
    "decision_variables": ["수입 규제", "가격 프리미엄", "고객 현지화 요구"],
    "provisional": true
  }
}
```

전제변경 패턴은 보조 태그가 아니라 검색 가지를 만드는 기준이다. 각 핵심 전략가정마다
그 가정을 약화·강화하거나 적용 시점을 바꿀 수 있는 패턴을 고른 뒤 영향 경로를 연결한다.
뉴스 주제가 비슷하다는 이유만으로 같은 의사결정에 묶지 않는다.

방향 변화와 별도로 `수준·범위 이탈`을 후보 발굴의 보조 렌즈로 쓴다. 가격·물량·재고·
가동률·스프레드·계약 조건이 동일 정의·단위·시장 기준의 전고점·전저점 또는 장기 범위를
크게 벗어나면 재심사하되, 이는 새 분류값이나 자동 발행 요건이 아니다. 비교 기준의
연속성, 이탈 폭과 지속성, 실물지표 또는 구조적 원인의 동행, 회사 의사결정의 허용구간과
바꿀 결정, 복귀·반증 조건을 확인하지 못하면 관찰 지표로 남긴다.

## 조사 단위: 커버리지 셀

URL이나 키워드 수가 아니라 다음 속성을 가진 하나의 `coverage_cell`로 관리한다.

`회사 × 사업축·경영 Function × 영향 경로 × 변화 유형 × 지역·시장 × 시간 구간`

이 표현은 가능한 값의 Cartesian product를 미리 생성하라는 뜻이 아니다. 먼저
`의사결정 질문 → 전략가정 → 영향 경로`가 성립하는지 확인하고, 그 경로를 검증하는 데
필요한 변화 유형·지역·시간만 동적으로 붙인다. 존재하지 않거나 사업 전달 경로가 없는
조합을 미확인 빈칸으로 만들지 않는다. 셀은 `queued`, `active`, `checked`, `closed` 중
하나로 관리하고, 한 번에 모든 셀을 펼치지 않고 우선순위가 높은 셀만 활성화한다.

각 coverage cell은 하나 이상의 `전제변경 패턴`을 가진다. 이 축은 URL 수를 늘리기 위한
분류가 아니라 익숙한 뉴스만 반복 수집하는 편향을 막는다.

- 대체수요: 다른 기술이 총수요가 아니라 특정 제품 수요를 제거하는가
- 시장접근 규칙: 세율 외의 데이터·원산지·인증이 판매자격을 가르는가
- 원료 병목: 최종 제품보다 희소한 투입재가 경쟁력을 가르는가
- 무역흐름 역전: 금지·제한 해제로 원료나 물량의 목적지가 바뀌는가
- 정책 결합: 별개 규제가 함께 적용될 때 제품 믹스나 채널 수익성이 바뀌는가
- 고객행동 간극: 전망과 달리 실제 계약·CAPEX·양산 일정이 먼저 움직이는가
- 원가구조 변화: 기술·정책이 비용 우위의 지배변수를 바꾸는가
- 시점 간극: 발표일과 효력·납품·손익 인식 시점이 의사결정 기한을 앞당기는가

각 셀의 후보에는 별도로 `signal_role`과 `signal_origin`을 붙인다. 이 두 값은 탐색축을
늘리기 위한 분류가 아니라 외부 변화와 자사 실행 소식을 섞지 않기 위한 출처 역할이다.
외부 시장·정책·경쟁사·거래상대 변화는 `core_market_signal`, 자사·자회사의 투자·증산·
계약·실적·공정 진척은 `execution_context`다.

- 사업축: 철강, 리튬, 전략광물, 에너지
- 경영 Function: 전략·투자, 영업·고객, 구매·공급망, 생산·운영, 기술·연구개발,
  재무, 인사·조직 중 실제 영향 경로가 있는 항목
- 영향 경로: 가격, 원가, 물량, 계약, 투자, 운영, 현금흐름 등 실제 사업 전달 경로
- 변화 유형: 정책·규제, 수급·가격, 경쟁사, 투자·프로젝트, 공급망·물류,
  고객·계약, 기술·운영, 재무·실적
- 지역·시장: 해당 조사에서 사업 영향 경로가 성립하는 국가, 권역, 거래 시장
- 시간 구간: 조사 기준일과 검색 시작·종료일. 마지막 성공 실행보다 설정된 겹침
  일수만큼 앞에서 다시 확인한다.

기술·국가·프로젝트 목록을 무한히 열거하지 않는다. 먼저 회사의 가격·원가·물량·계약·
투자·운영으로 전달되는 경로를 세우고, 이를 확인하는 데 필요한 대상만 탐색 셀에 넣는다.
영향 경로가 불명확한 일반 산업 동향은 우선순위를 낮추거나 제외한다.

## 신규 정보와 사건 묶음

`new_url ≠ new_information`을 불변 규칙으로 둔다. 새로운 정보는 다음 중 하나일 때만
인정한다.

1. 기존에 없던 사건이 확인됨
2. 기존 사건에 새로운 원자적 Claim이 추가됨
3. 기존 Claim의 신뢰도·상태·검증일이 바뀜
4. 발표·승인·자금·건설·가동·출하 등 사건의 이행 상태가 바뀜
5. 회사 영향이나 의사결정 시한 평가가 바뀜
6. 기존 결론을 반증하거나 적용 범위를 제한하는 근거가 추가됨

같은 사건을 여러 Source가 다루면 발견 단계의 run 안에서 `event_key`로 묶는다.
`event_key`는 `주체 + 행위 + 대상 + 사건일·효력일`의 정규화된 조합이며 URL이나 기사
제목으로 만들지 않는다. 현재 저장소에 별도 Event 엔터티 계약이 없으므로 Source·Claim
사이에 지원되지 않는 영속 객체를 임의로 만들지 않는다. 대신 `event_groups`에 Source,
후보 Claim, 현재 이행 상태를 기록해 보도량이 중요도로 오인되는 것을 막는다.

## 후보 발굴 퍼널과 심층 근거 패킷

최근 3년처럼 범위가 넓은 핵심 전략 이슈 발굴은 발견된 URL을 바로 이슈 목록으로
바꾸지 않는다. run에서 다음 네 단계의 건수와 이동 사유를 보존한다.

`발견 후보 → 중복 통합 사건 → 심층 검증 후보 → 핵심 전략 이슈`

- 발견 후보: 제목·초록·목록에서 영향 경로 가능성이 확인된 사건 후보
- 중복 통합 사건: 재인용과 동일 사건의 후속 보도를 `event_key`로 묶은 단위
- 심층 검증 후보: 사업영향도 또는 긴급도 4~5점 가능성이 있고 바꿀 결정이 명확한 사건
- 핵심 전략 이슈: 독립 Signal이 같은 전략가정과 결정 안건으로 수렴하고 근거 패킷을
  충족한 문서급 현안

전사 범위 조사에서는 원칙적으로 사업축마다 서로 다른 영향 경로의 발견 후보를 8건
이상 확보한 뒤 승격 심사를 시작한다. 8건 미만이어도 세 가지 독립 탐색 전략에서 신규
고영향 후보가 나오지 않고 고위험 빈칸과 다음 트리거를 기록했다면 닫을 수 있다. 이
경계는 낮은 가치의 Signal을 채우는 할당량이 아니라 익숙한 사건 몇 건에서 조기에
멈추는 편향을 감지하기 위한 것이다.

핵심 전략 이슈 한 건의 심층 근거 패킷은 원칙적으로 다음을 갖춘다.

- 서로 다른 원문 5개 이상. 동일 보도자료의 재인용은 한 개로 계산
- 독립 탐지 채널 3개 이상. 권위 있는 정책 원문만으로 규칙 사실이 확정돼도 시장 전달
  경로와 회사 노출은 다른 채널로 확인
- 규칙·정책, 시장·물리 지표, 고객·경쟁사 행동, 회사 노출·실행, 반증·지역 예외 중
  적용 가능한 역할을 구분한 출처 구성
- 결론을 약화시키거나 적용 범위를 제한하는 원문 1개 이상. 찾지 못했다면 검색 전략과
  `현재 확인된 반대 근거 없음`을 기록
- 핵심 수치·날짜·상태를 쪼갠 원자 Claim, 정량 영향의 지배변수와 중복계상 경계

다섯 개 원문이 모든 이슈의 기계적 최소치는 아니다. 법령·공식 통계처럼 적은 원문으로
사실을 확정할 수 있거나 공개자료가 구조적으로 제한된 경우에는 예외 사유, 빠진 근거
역할, 신뢰도 하향, 다음 확보 대상을 명시한다. 반대로 원문 수가 많아도 같은 발표를
재인용한 자료뿐이면 근거 패킷을 충족하지 못한다.

## 네 단계 탐색

### 1. 발견

낮은 비용으로 후보를 넓게 찾는다. 기업 뉴스룸·IR·공시, 정부·규제기관·인허가,
거래소, 산업단체의 RSS·API·사이트맵·목록·공개 원문을 우선한다. 이 단계에서는 제목,
발행자, 게시일, canonical URL, 예상 coverage cell, `event_key`, 신규성 유형만 판정하며
Claim을 만들지 않는다.

대상 회사 뉴스룸·IR의 높은 검색 노출을 시장 변화의 높은 중요도로 오인하지 않는다.
회사명을 언급하지 않아도 가격·수급·정책·경쟁사·고객·물류에서 회사로 이어지는 영향
경로가 명확한 후보를 우선 수집한다. 회사 발표는 노출 규모와 실행 상태를 확인하는
맥락 후보로 별도 보관한다.

발견 쿼리는 회사명 결합형만 쓰지 않는다. `대체기술 + 상용 계약/납품`, `원료 + 수입
재개/품질 기준`, `시장접근 + 데이터/인증`, `정책 A + 정책 B + 제품 믹스`, `전망 + 실제
구매계약`처럼 전제를 깨는 행동을 먼저 찾고, 그 뒤 회사의 노출을 연결한다.

후보를 심층 검증으로 넘기기 전에 회사 관심도 판정표를 작성한다. 회사 근거는 최신
사업보고서를 기본선으로 삼고 IR, 공식 포트폴리오, 투자·프로젝트 공시로 갱신한다.
외부 사건과 회사의 제품·자산·고객·조달·기술·지역·투자계획 중 무엇이 연결되는지,
그 연결이 가격·원가·물량·계약·투자·운영 중 무엇을 바꾸는지 적는다. 직접 노출이
확인되면 `핵심 관심`, 공식 진입 검토나 조건부 노출만 확인되면 `조건부 관심`, 연결
근거와 바꿀 결정이 없으면 `비대상`으로 판정한다.

### 2. 커버리지 점검

후보를 coverage cell에 배치하고 다음을 찾는다.

- 아직 확인하지 않은 고영향 셀
- 최근 확인이 오래된 셀
- 특정 언어·지역·발행자에 치우친 셀
- 공식 발표만 있고 물리적 이행 자료가 없는 셀
- 성공 자료만 있고 연기·중단·비용·허가 실패 신호가 없는 셀
- `execution_context`가 30%를 넘거나 특정 프로젝트·설비가 과반인 사업축

결과가 많은 셀을 더 검색하는 대신 중요한 빈칸으로 다음 예산을 이동한다.
신규 run의 사업축별 `core_market_signal` 70%는 자사 뉴스 편중을 감지하는 품질 경계다.
발행 건수를 맞추는 생성 quota로 사용하지 않는다. 70% 미만이면 먼저 독립 외부 채널과
비어 있는 고영향 셀을 다시 확인하되, 유효한 외부 변화가 없으면 영향 경로가 약한 일반
뉴스를 채우지 않는다. 미달 원인, 추가로 확인한 전략, 남은 고위험 빈칸과 다음 트리거를
run에 남긴다. 하나의 run 비율뿐 아니라 최근 여러 run에서 같은 사업축의 편중이 반복되는지도
사후 누락 감사에서 확인한다.

### 3. 검증

사업 판단을 바꿀 가능성이 있는 후보만 본문을 읽고 Source·Claim으로 등록한다.
검증비용은 Claim 성격에 따라 차등화한다. 동일 보도자료의 재인용은 독립 발견 채널로
세지 않는다.

- 공식 사실: 법령·관보·규제기관 원문처럼 권한 있는 1차 자료 하나로 확인할 수 있다.
- 이행 상태: 회사 발표만으로 완료를 확정하지 않고 인허가·자금·공사·생산·출하 중
  적용 가능한 물리적 또는 독립 채널을 추가 확인한다.
- 시장 영향: 가격·수급·고객·경쟁사 등 서로 다른 인과 채널에서 근거를 확인하고,
  출처의 전망과 AI의 영향 해석을 구분한다.
- 구조적 Trend: 통계, 고객·경쟁사 행동, 공급망·기술 연결, 가격·점유율 시계열 중
  최소 두 종류의 독립 채널과 결론을 약화시키는 근거를 함께 확인한다.

### 발표 이후 이행 상태

프로젝트·정책·계약·설비 사건은 적용 가능한 범위에서 다음 상태 흐름으로 추적한다.

`announced → approved → funded → construction → commissioned → ramp_up → commercial_operation`

각 단계에서 `delayed`, `suspended`, `cancelled`로 분기할 수 있다. 자료가 없으면 앞 단계가
자동으로 다음 단계가 되었다고 추정하지 않는다. 공개 확인 상태는 `confirmed`,
`contradicted`, `unknown`, `blocked`, `not_applicable`, `stale` 중 하나로 기록한다.
`stale`은 과거 확인 자료는 있으나 재검증 기한 이후 현재 상태를 확인하지 못한 경우다.

### 4. 반증 탐색

고영향 후보에는 최소 한 번의 반대 방향 탐색을 수행한다.

- 발표와 실제 생산·출하·집행 상태가 다른가
- 발표일과 효력일 또는 손익 인식 시점이 다른가
- 경영진 발언과 CAPEX·물량·계약 행동이 다른가
- 공식 후속 수치가 최초 보도나 시장 통념과 충돌하는가
- 연기, 중단, 취소, 자금 철회, 허가 거절, 비용 초과가 있는가

반대 근거가 없으면 `현재 확인된 반대 근거 없음`으로 기록한다. 결론을 흥미롭게 만들기
위해 반대 근거를 추정하지 않는다.

구조적 전환 후보는 한 번의 기사 급증으로 확정하지 않는다. 공공 통계·전망, 고객·경쟁사
실제 투자행동, 기술·원료 선호의 물리적 연결, 가격·점유율 시계열 중 둘 이상의 독립
채널이 같은 방향을 가리킬 때 Trend 후보로 올린다. 총시장 성장, 지역별 예외, 대체 기술의
성능 우위처럼 결론을 약화시키는 근거도 별도로 검색한다.

## 적응형 조사 예산

LLM 호출 횟수나 검색 결과 수를 모든 조사에 동일하게 고정하지 않는다. 각 coverage
cell의 상대적 우선순위는 허위 정밀도를 가진 계산식으로 점수화하지 않는다. `high`,
`medium`, `low`와 한 줄 근거로 충분하다.

- 우선순위 증가: 잠재 사업영향, 긴급성, 불확실성, 정보 노후도, 변화 가능성이 커짐
- 우선순위 감소: 접근·검증 비용이 커지거나 다음 탐색의 예상 정보이득이 작아짐

다음 상황에서는 조사 예산을 늘린다.

- 잠재 사업영향 또는 긴급도가 4~5점인데 독립 검증이 없다.
- 수치·일정·효력일·이행 상태가 출처 사이에서 충돌한다.
- 고위험 coverage cell이 미확인 상태다.
- 현지어·정부·고객·공급망 등 독립 탐지 채널이 비어 있다.
- 신규 정보가 기존 결론이나 대응 시한을 바꿀 가능성이 있다.

다음 상황에서는 예산을 줄이거나 탐색 가지를 닫는다.

- 신규 결과가 동일 원문의 재인용 또는 이미 등록된 본문이다.
- 영향 경로가 없거나 사업 판단을 바꿀 가능성이 낮다.
- 반복 쿼리에서 독립된 신규 원문과 결론 변경 정보가 나오지 않는다.
- 접근 통제 때문에 더 진행할 수 없고 공개 대체 출처도 확인했다.

## 중단 조건

고정 검색 횟수만으로 완료를 선언하지 않는다. 다음 조건이 충족되면 해당 탐색 가지를
중단할 수 있다.

- 적용 가능한 서로 다른 탐색 전략 세 종류에서 신규 고영향 후보가 없다.
- 신규 독립 1차 출처 또는 결론을 바꾸는 Claim이 없다.
- 미확인 고위험 coverage cell이 없거나, 남은 셀의 미확인 이유와 후속 트리거가 있다.
- 공식 발표, 독립 검증, 실패 신호 중 해당 사건에 적용 가능한 채널을 확인했다.

탐색 전략은 쿼리 문구가 아니라 발견 경로가 달라야 한다. 다음 중 사건에 적용 가능한
전략을 고른다.

- broad semantic search: 회사명 없이 전제변경 패턴과 영향 경로를 넓게 확인
- primary-source search: 정부·규제기관·관보·공시·산업단체 원문 확인
- local-language search: 영향 지역의 현지어·별칭·법령명으로 확인
- counterparty search: 고객·경쟁사·공급사·금융기관의 행동 확인
- failure-signal search: 연기·취소·허가 거절·비용 초과·자금 철회 확인
- follow-up execution search: 발표 후 승인·자금·건설·가동·출하 상태 확인

같은 검색엔진에서 단어만 바꾼 세 쿼리는 서로 다른 전략 세 개로 세지 않는다. 특정
사건에 적용 가능한 전략이 세 종류보다 적으면 적용한 전략과 제외 이유를 기록하고,
남은 고위험 빈칸의 다음 트리거가 있을 때만 닫는다.

검색되지 않았다는 사실을 사건이 없다는 증거로 사용하지 않는다. 기간·출처·언어·접근
제한 때문에 확인할 수 없으면 `unknown` 또는 `blocked`로 남긴다.

## 독립 탐지 채널

같은 검색엔진에서 문구만 바꾼 결과를 서로 독립된 확인으로 보지 않는다. 조사 주제에
적용 가능한 다음 채널 중 둘 이상을 확인한다.

- 기업 행동: 뉴스룸, IR, 공시, CAPEX·가이던스
- 정부 행동: 법령, 관보, 규제기관, 무역구제, 인허가
- 물리적 행동: 생산, 출하, 항만, 재고, 가격, 가동 자료
- 거래 상대 행동: 고객 조달, 경쟁사 계약, 공급사 증설
- 실패 신호: 연기, 취소, 자금 철회, 허가 거절, 비용 초과
- 후속 이행: 발표 후 30·60·90일 실제 이행
- 현지 자료: 영향 지역의 현지어 공식 자료

모든 사건에 모든 채널을 억지로 적용하지 않는다. 적용하지 않은 채널은 이유를 남긴다.
기업 행동 채널에서 대상 회사·자회사의 발표만 확인된 경우 독립 외부 채널로 세지 않는다.
경쟁사·고객·거래상대의 공식 발표는 `competitor_counterparty` 외부 발생원으로 분리한다.

저장형 조사에서는 `.system/runs/<run-id>.json`에 기존 쿼리·결과·접근 실패와 함께 다음
내용을 기록한다. 기존 run 스키마가 자유 형식이면 `coverage` 객체 안에 둔다.

중복을 줄이는 run 상태이며 별도 영속 Event 레코드를 대신하지 않는다. 값이 없으면
빈칸으로 숨기지 말고 이유를 기록한다.

## 완료 판단과 보고

조사 완료 시 최소한 다음을 설명할 수 있어야 한다.

- 어떤 사업 의사결정 공간을 확인했는가
- 어떤 전략가정과 전제변경 패턴을 확인했는가
- 어느 독립 채널에서 무엇을 확인했는가
- 어느 고위험 빈칸을 해소했는가
- 무엇이 여전히 미확인이고 왜 그런가
- 어떤 사건의 이행 상태가 바뀌었고 무엇이 오래되었는가
- 왜 추가 탐색의 정보가치가 낮다고 판단했는가
- 어떤 사건이나 날짜가 재탐색을 발생시키는가
- 후보 퍼널의 각 단계에서 몇 건이 남았고 무엇 때문에 탈락했는가
- 승격 이슈별 원문 수, 독립 채널 수, 반증 근거와 빠진 근거 역할은 무엇인가

승격 이슈의 근거 패킷이 닫히면 검색 결과를 바로 사람 화면에 투영하지 않는다. run의
`editorial_plans`에 독자 질문, 한 문장 결론, 핵심 숫자, 통념과 간극, 바꿀 결정,
다음 촉매와 시각화 후보를 기록한 뒤 독자용 리포트 편집 단계로 넘긴다. 원문 수와 독립
채널 수는 조사 완전성 설명에 남기고, 독자용 제목·소제목에서는 시장 결론보다 앞세우지
않는다.

`전체 인터넷 조사 완료`, `관련 자료를 모두 확인`처럼 검증할 수 없는 표현을 쓰지 않는다.
대신 조사 기간, 확인 채널, 미확인 범위, 중단 근거를 함께 제시한다.

## 사후 누락 감사

월간 또는 분기 감사에서 뒤늦게 중요해진 사건을 표본으로 뽑아 최초 탐지 실패 원인을
다음 중 하나로 분류한다.

- 키워드·별칭 누락
- 출처·채널 누락
- 현지어·지역 누락
