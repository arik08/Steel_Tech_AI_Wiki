# Steel Intelligence 저장소 지침

- 조사·검색·보고 전에 상위 `WIKI-SETTINGS.md`를 읽으세요.
- 사용자가 검색 도구를 지정하지 않아도 Wiki의 기업·기술·프로젝트·출처와 관련된 자연어 질문이면 자동으로 `steel_intel.py search`를 실행하고 Claim·Source 원문까지 확인하세요.
- 사용자에게 도구명이나 “Wiki 기반” 같은 특별한 요청 문구를 요구하지 마세요. 조회는 사용자가 별도로 저장을 요청하지 않는 한 읽기 전용입니다.
- `.system/raw/`의 등록 원문을 수정하거나 삭제하지 마세요.
- 수치·날짜·일정·투자비·용량은 `.system/claims/`의 원자적 claim으로 관리하세요.
- 기존 주장과 다른 값은 자동 덮어쓰지 말고 `.system/reviews/pending/`으로 보내세요.
- 오래된 정보는 삭제하지 말고 `superseded`, `disputed`, `cancelled`, `stale`로 전환하세요.
- 사람은 `index.md`에서 시작하고, 검토할 항목은 `REVIEW.md`에서 확인하세요.
- 기업·기술·프로젝트·출처 Markdown 페이지는 claim과 원문의 사람이 읽는 통합 투영본입니다.
- 기술·기업·프로젝트 통합 문서는 나무위키형 백과사전처럼 `한눈에 보기`, 개요,
  원리·구성, 전체 연혁, 현황, 쟁점, 출처를 자연스럽게 따라갈 수 있게 작성하고
  시스템 필드나 최근 상태만 나열하지 마세요.
- 프로젝트 페이지에는 날짜가 확인되는 발표·착수·건설·실증·가동 목표·연기·중단·
  취소 이력을 모두 시간순으로 표시하세요.
- 사실과 AI 분석을 분리하고 모든 핵심 사실에 claim ID와 source ID를 표시하세요.
- 설비·공정 이미지가 이해에 필요하면 `add-image`로 Source에 연결하고 캡션·유형·원문·권리 상태를 기록하세요.
- 이미지 검색 썸네일만 저장하지 말고 원문을 확인하세요. 권리가 불명확하면 내려받지 않고 `link_only`로 등록하되, 인터넷 연결이 유지되는 전제에서 공식 원문 이미지 URL을 대표 이미지로 직접 표시할 수 있습니다. AI 재구성은 실제 설비 사진과 구분하세요.
- 기술·기업·프로젝트 통합 문서 상단에는 대표 이미지가 최소 1장 있어야 합니다.
  로컬 복제 또는 `link_only` 원격 표시가 가능한 공식 이미지를 확보하지 못하면 출처 기반 AI 재구성을
  `ai_reconstruction`·`ai_generated`로 등록하세요.
- 대표 이미지는 설비 내부 절개도·장치 구성도, 실제 설비 본체·내부·운전 사진,
  공정 흐름도, 공장 외관 순으로 우선하세요. 인물이 중심인 기공식·준공식·협약식·
  악수·단체 사진은 기술 대체 이미지가 없을 때만 보조 자료로 쓰고 대표 이미지로
  사용하지 마세요. 범용 공급사 도면은 프로젝트 준공도(as-built)가 아님을 캡션에
  명시하세요.
- 일반 설비·공사·외관 사진은 데스크톱 본문 폭의 60~70%로 가운데 정렬하고,
  내부 절개도·장치 구성도·특허·학술 그림·공정도처럼 세부 판독이 필요한 자료만
  약 90%까지 넓게 표시하세요. 모바일에서는 본문 폭을 사용하세요.
- 검색 범위, 쿼리, 접근 실패를 `.system/runs/`에 기록하세요.
